# Execution environment ownership

The application uses Pi Durable 1.0.4. `DurableChatService.open` installs one `HarnessOptions.env` function from an `ExecutionComposition`. Pi calls that function for tools, prompt preparation and `TaskRuntime.env()`. The production composition is local; there is no production target document, host registry or remote transport.

`src/pi/execution/composition.ts` is the host integration seam. `open({ execution: local => composition })` can replace the resolver, supply environment facts and request scopes, install application extensions, and initialize application state in `conversationCreated`. A resolver returns a public `ExecutionEnv` directly. It may return `undefined` or throw for an unavailable selection; tools report that failure without selecting a different backend. The independent environment in `tests/helpers/independent-env.mjs` demonstrates this seam using a separate filesystem and a test-only durable document.

The stable extension name is still `local-bash`. It registers `read`, `write`, `edit` and `bash` once. Read/write/edit use Pi's public factories, including the bounded 1.0.4 read implementation. Pure `wrapTool` registrations acquire their request scope inside `execute` and release it in `finally`; neither hook ordering nor an imagined Pi disposer owns cleanup. Edit admission delegates the complete public environment interface. The shared bash adapter calls only `api.env.exec` and uses the public stdout/stderr metadata. It preserves the existing split-stream head previews, exit status and persistent artifact references, which differ from Pi's stock combined-tail presentation.

## Local resource lifetime

The local resolver reads the committed workspace ID and agent cwd. Constructing this facade or resolving lexical paths opens no database, holds no workspace lease and creates no disposable reader. The workspace UUID remains the persistence and exclusion key; every environment has its own identity because its temporary namespace is distinct.

Direct callers own the returned environment. Successive filesystem and exec operations on that environment share its lazy temporary tree until `cleanup(context)`. Each direct operation takes a short workspace lease. Readers close independently and never retain a whole workspace lease across calls. Active direct resources register lazily with the runtime so service shutdown can seal and drain them before closing shared storage. Task code using `runtime.env()` must close its environment in `finally`; Pi does not do so automatically.

For compound host operations, `acquireWorkspaceExecutionScope(env, context)` returns a bound environment and an idempotent `release()`. Queued acquisition and delivered scopes remain owned by that facade until release: its cleanup cancels admission, closes its scopes and awaits drainage, including a lease acquired while cancellation wins before delivery. The shared tool scope uses that helper around admission, SDK execution, edit matching, writes and artifact formatting. Each tool scope has a fresh temporary tree. Its bound `exec` uses the same lease, so it cannot reacquire its own workspace queue. Closing a request scope closes its readers and drains admitted work without shutting down an unrelated environment consumer. Tool-only facades stop occupying the runtime owner set after their final scope and pending work settle. The service owns `stop()` and awaited `close()` of the composition.

Expected environment failures, including cancellation, use Pi's typed `Result` errors. At the tool boundary the wrapper preserves the caller's cancellation reason. Runtime shutdown seals admission and cancels both queued and active work; filesystem drainage remains an awaited operation.

Binary readers retain the opened file's identity. Reads see in-place changes and continue to read that file after rename, atomic replacement of its path, or final unlink. Persistent range reads use SQLite `substr` rather than fetching the complete BLOB; the public line scanner reads in 64 KiB chunks. Open persistent inodes remain charged against quota until their final reader closes. The process-local pin registry coordinates connections; opening a store reclaims unpinned, unnamed inodes left by a process crash. This uses the existing schema and does not change workspace identities. Current-state copies exclude unnamed reader-owned inodes.

An environment admits at most 64 open readers. Until a reader is delivered, its opener owns rollback of the slot, inode pin and temporary handle. Cancellation during retention, registration, lease completion or text-reader wrapping releases those resources before returning an error. Temporary readers follow live file identity and retain removed or replaced bytes within the bounded temporary namespace. Directory readers keep a bounded name snapshot, page current entry metadata, and skip entries removed during enumeration. They do not retain a workspace lease. Closing a reader is independent and idempotent; environment cleanup also awaits an independently started asynchronous reader close. Stale readers reject use after close. `truncateFile` changes file length, and `flushFile` validates the file after its writes have already committed through SQLite.

Watching is intentionally unsupported: `watch` returns the typed `not_supported` error, "The local virtual filesystem does not provide reliable change notifications." It creates no watcher or cleanup obligation. The implementation does not manufacture successful watch events from incomplete local notifications.

## Configuration and persistence

`AgentDoc` owns model, thinking level, cwd, instructions and explicit tool/extension selections. New chats leave tool and extension selections unset, so Pi resolves the current host defaults. Pi also owns historical agent selection on forks and inherited agent state for task-owned conversations. Application initialization does not rewrite those selections.

`WorkspaceDoc` stores only the local workspace UUID and its origin. The creation hook assigns a fresh workspace to each new, forked or task-owned conversation. Local forks therefore get an empty filesystem; reopening retains the committed workspace identity and files. Workspace initialization does not track capability rollouts or repair earlier chat formats. Unsupported old records have no preservation path, and this code does not automatically delete data.

`DurableChatService.configureExecution(id, { cwd }, updateState)` commits cwd and any application selector document in one transaction. It scans that conversation's durable tasks on the same transaction line: `pending`, `running`, `waiting` and `completing` tasks all block configuration, including custom/background tasks and aborted work whose cleanup has not settled. Agent live state and the pending inbox are checked as well. The application callback runs only after readiness succeeds, and both values roll back if validation fails. This does not change the existing model-settings policy after offline abort intent. A future selector that follows historical agent configuration should use `history: 'rewindable'` and `fork: 'asOf'`. Task-owned conversations inherit `AgentDoc`; custom document inheritance belongs explicitly in the creation hook. The fixture proves these behaviors without adding fake host types to production state.

## Portable edit source admission

The shared edit policy uses a single opened public `BinaryReader` for metadata and source bytes, never a subsequent pathname lookup or backend whole-file `readTextFile`. It requests at most 64 KiB per read and receives at most the 8 MiB source ceiling plus one detection byte before rejecting growth. Replacing the pathname cannot redirect that reader to a different file; growth of the opened inode remains bounded. This guarantees the same source admission for every conforming environment.

Strict UTF-8 validation occurs before Pi receives the source. Chunk decoding carries at most three trailing bytes into the next chunk and verifies complete chunks by round-tripping their bytes, preserving repeated BOMs, CRLF, valid replacement characters and split multibyte scalars. It does not rely on `TextDecoder` fatal/stream options that differ across runtimes. Invalid UTF-8 returns an `invalid` file result without mutation. Reads cooperate with cancellation, and the opened reader closes in an uncancelled `finally` on success, rejection or cancellation. Pi still owns all edit matching and replacements.

Service command serialization is per conversation. `ChatRuntime` retains ordered authentication and lifecycle admission but awaits admitted send, cancel and settings operations outside its global queue. A regression with a cancelled independent command deliberately held in drainage proves that another local chat can proceed, same-chat work remains ordered, and backgrounding stops admission before awaiting cleanup. Existing auth replacement and offline model-setting tests remain intact.

## Output and artifacts

Formatting receives an optional narrow `ArtifactWriter`. The local adapter exclusively creates ordinary workspace files beneath `.bash-output` and `.edit-output`, rejects output-directory symlinks, and checks cancellation. The shared tools know neither SQLite nor the local interpreter. An environment without an artifact writer still runs every tool and reports when complete output or a patch cannot be saved.

Bash retains a head preview of at most 24 KiB and 800 lines per stream and counts received bytes incrementally. With an artifact writer, full capture is limited to 8 MiB per stream; exceeding that limit discards the full capture and reports it unavailable. Without a writer, only the bounded preview is retained. It never requests a coalesced output window, so stdout and stderr remain distinct. The tool normalizes the timeout to a default of 10 seconds and a maximum of 30 before delegating. Nonzero exits and environment failures remain visible; timeout uses exit status 124 with the partial-mutation warning. Existing transcript details and artifact paths retain their presentation format.

Local execution supports script strings and literal argv, cwd, virtual environment overrides, cancellation, typed deadlines, output callbacks and temporary spill files. It never inherits the phone process environment. The engine buffers output and delivers stdout followed by stderr; callback stream identity is accurate, but relative timing between the streams is unavailable. It delivers every output chunk rather than applying the optional coalesced-window optimization. Direct callers own temporary spills until environment cleanup; persistent shared-tool artifacts use the separate writer.

`spawn_error` is reserved for launch/admission failure. Once execution starts, an unexpected execution failure uses `unknown` (Pi 1.0.4 has no separate post-execution/storage error code). If saving a spill fails after completion, the error explicitly states the completed exit code and that output could not be preserved; already delivered callbacks and committed mutations remain real. The incomplete spill is removed when possible and never advertised as complete output. Callback failures retain `callback_error`, while deadlines and cancellation retain their specific codes. Stock multi-form consumers therefore cannot mistake an output-storage failure for permission to execute the command again.

Two intentional limits changed during integration. The interpreter command ceiling is 10,000 and its loop ceiling is 4,096, allowing the upstream 2,000-line shell case, which executes multiple commands per iteration and an additional loop condition. Other source, memory, output, parser, work and time ceilings remain enforced. Shared full-output capture now has the explicit 8 MiB per-stream bound above; a backend producing more cannot grow the phone's collector indefinitely. Synthetic failure diagnostics are separate from received-byte counts.

### Follow-up review remediation

A subsequent independent review demonstrated six additional failures despite the earlier passing suite. Its saved probes were reproduced before fixes. The resulting permanent coverage exercises behavior through the public environment and production service hooks:

| Finding | Resolution and regression evidence |
| --- | --- |
| 1. Custom tasks outlive environment selection | Transactional nonterminal-task scan rejects configuration before the application callback, including aborted background work still draining. `execution-configuration.test.mjs` holds real task-owned environment work and allows configuration only after settlement. |
| 2. Portable edits corrupt invalid UTF-8 or overread growth | Same opened reader, strict chunk decoding and bounded receiving. `portable-edit-source.test.mjs` uses the stock Node environment for invalid bytes, growth, pathname replacement and scalar boundaries; `execution-composition.test.mjs` verifies committed rejection reaches the next model request without mutation. |
| 3. Queued scope escapes facade cleanup | Acquisition and delivered scopes follow owner cancellation and drain. `workspace-runtime.test.mjs` covers queue and delivery races, stale writes, and facade/runtime shutdown with held scopes and queued scope/direct work. |
| 4. Cancelled reader admission leaks resources | Allocation rollback before delivery releases slots, inode pins and temporary handles. Repeated binary/directory/text/temporary cancellation regressions subsequently open valid readers and inspect cleanup/retention behavior. |
| 5. Historical pre-rollout fork misses capabilities | The old capability rollout and its preservation machinery have been removed. Current conversations use Pi defaults and native agent inheritance; workspace tests cover current-format reopen, historical selections and fresh fork/owned namespaces. |
| 6. Failed spill claims command never started | Post-start failures cannot return `spawn_error`; completed spill failure reports `unknown` with exit status context. `execution-shell-errors.test.mjs` proves committed mutation, received output, incomplete-artifact removal, no stock alternate-form retry and unchanged launch/admission error codes. |

Independent review of the remediation caught an additional cleanup ordering deadlock: queued work waited for a scope whose release cleanup had postponed. Cleanup now initiates owned-scope release before awaiting the combined work. Four regressions failed before that change and pass after it. The reviewer independently reran the reproduction and 53 focused cases, then reported no remaining actionable finding. Integrated verification passed all 567 application tests, both platform Hermes exports, and the iOS native checks above. Remediation logs are retained under `.expo/execution-env-refactor/review-fixes/`. The follow-up did not run physical-device or live-account feature checks.

Workspace rollout compatibility was subsequently removed under the current product policy. [Workspace state tests](../tests/workspace-state.test.mjs) cover registry defaults, identity/files across reopen, explicit selections, historical agent configuration, fresh fork namespaces, owned inheritance and atomic execution configuration. Independent review found no remaining issue in that removal. The full suite passed with 562 application tests and 37 package tests after removing legacy-only cases; lint, typecheck and diff checks also passed. No native or device checks were repeated for this cleanup.

The implementation specification remains [execution-env-refactor.md](execution-env-refactor.md). Production execution remains local. The later custom backend supplies an `ExecutionComposition` at `DurableChatService.open`, reads its application document in `resolve`, configures any request ownership through `toolPolicy.scope`, and owns `stop`/`close`; shared tools require no backend branch. The SSH investigation remains later-feature background.
