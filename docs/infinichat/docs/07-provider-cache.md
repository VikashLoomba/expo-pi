Provider prompt caching is pi-ai’s own. Each conversation’s persisted provider session identity is forwarded with every request, the Anthropic adapter marks the static system/tools prefix and the request end itself, and other providers cache prefixes without marks. OptChat keeps the request prefix cacheable: tools, then the static system prompt, then the saved view as one text block, then the new message or compaction task. Device state, the agents at work and other per-turn state follow the view. The main and compaction views batch on their own sizes, so a batch of one does not rewrite the other’s cached prefix. Summaries use the same system prompt and offered tool schemas as turns, so turns and compactions share that static prefix; UniiChat’s compactions send the system prompt without tools, which this port defers with the rest of the caching work.

UniiChat’s mark on the last whole four-line view block and its single flight, in which a call waits while another writes the prefix it would read, are not implemented. Pi exposes no provider-neutral API for an interior breakpoint, and OptChat carries no provider payload shapes. Retention matches: UniiChat’s marks and pi-ai’s default `short` retention both keep Anthropic’s five-minute entries. Providers that match exact prefixes automatically still read an unchanged view prefix from the cache; Anthropic reads the static prefix and writes the view again. Expiry, model or account changes and batched view rewrites miss the cache as before, and UniiChat’s cache test, which requires 95% of input read from the cache, does not apply.
