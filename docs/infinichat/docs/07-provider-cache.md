# Provider caching

Sources: [OptChat §3.3](https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449), [native prompt API](https://github.com/earendil-works/pi/blob/71023aec1546d6d677a65669c5665c0927ce0dd0/packages/durable/docs/spec.md#L3431-L3559), [Pi AI public API](https://github.com/earendil-works/pi/blob/71023aec1546d6d677a65669c5665c0927ce0dd0/packages/ai/src/index.ts).

Provider prompt caching is pi-ai’s own. Each conversation’s persisted provider session identity is forwarded with every request, the Anthropic adapter marks the static system/tools prefix and the request end itself, and other providers cache prefixes without marks. OptChat keeps the request prefix cacheable: tools, then the static system prompt, then the saved view as one text block, then the new message or compaction task. Device state, the agents at work and other per-turn state follow the view. The main and compaction views batch on their own sizes, so a batch of one does not rewrite the other’s cached prefix. Summaries use the same system prompt and offered tool schemas as turns, so turns and compactions share that static prefix.

The gist’s interior mark on the last whole four-line view block, its coordination of overlapping requests on one marked prefix, and its retention policy are not implemented. Pi exposes no provider-neutral API for an interior breakpoint, and OptChat carries no provider payload shapes. Providers that match exact prefixes automatically still read an unchanged view prefix from the cache; Anthropic reads the static prefix and writes the view again. Expiry, model or account changes and batched view rewrites miss the cache as before, and the gist’s measured hit rates do not apply.
