# Behavior-derived validation

[Guide index](../README.md) · [Behavioral coverage](09-validation.md) · [Pinned references](10-references.md)

Tests must assert the externally visible behavior this guide specifies rather than merely repeat implementation choices. Fake model responses can verify deterministic policy, native scheduling and captured requests without paid model calls. They do not establish summary quality, provider cache billing, or physical power-loss guarantees.

Run the package’s declared typecheck and test commands from its root. The implementation listings are regenerated by `python3 scripts/build-docs.py`; this requires every listed source file and does not synthesize missing code. Review the test files and captured requests alongside their assertions.


## Executable checks

- [Memory and summary tests](../test/memory-summary.test.mts): exact short sources, flattened merge inputs, bounded corrections with the single too-long note, cut replies, patient retries of every failure but the model’s own (thrown, non-retryable and unavailable-model ones included) without clipping, 64-way admission in message order with a merge first at a tie, failed leaves holding their places with retries off, frozen context, saved-view text budgets, UniiChat’s clip marker and the `MemoryDoc`, scratch and `BuildNode` migrations.
- [Independent guide oracles](../test/independent-guide.test.mts): the original rollback push comparison through 20,000 messages, due-order counterexample, admission races, pending batches, independent view batches, a `spawn` report admitted as a fresh turn and storage reopen.
- [Application tests](../test/app.test.mts): complete native assembly, fresh-turn isolation, the turn message after the view, a retried failure leaving only the final reply, a final failure’s cut text and `No reply:` note, the output-limit note, a stop’s cut text and note, an input a failed run left queued answered in a fresh turn with the view, an input prepared for a turn that ended before its submission starting a fresh turn, a stop keeping a pending note before its own, Stop ending agents whose `failed: stopped` reports take no turn, the `AppDoc` and `InputDoc` migrations, and a conversation that stored its first tool list offered the tools added since with the user’s instructions kept.
- [Tools tests](../test/tools.test.mts): prompt renaming and the subagents’ `SUB_HEAD`, native recall/images with the `id+0|` head, wrong-line answers, scalar pagination, output clipping, unclipped read pages and steering after the round.
- [Background-agent tests](../test/agents.test.mts): named agents from `spawn`, configured with their folder and effort and without the master’s prompt or tools, their first message the view, devices and numbered log, full reports with the zoom pointer, `tell` steering an agent at work through its one call and one report, a message told before the call reaches the agent joining its log with no stray reset, a call whose run fails reporting the failure and withdrawing what it was told, `tell` resetting an idle agent and sending its log, `zoom(name)` logs and unknown names, the captured summary cutoff, and the task, agent, report and agent-call migrations.
- [Native recovery tests](../test/recovery.test.mts): reopening during interrupted summary work, preserved saved views, resumed summary, and next-turn context isolation.
- [Linux storage tests](../test/node-storage.test.mts): exclusive writer, exact reopen, and acknowledged native data surviving process termination. These are not physical power-failure tests.

## Behavioral requirements

Satisfy each linked behavior and its acceptance check. Treat the gist’s algorithm examples and UniiChat’s cache measurements as explanatory evidence, not additional product APIs or guaranteed performance.

The requirements below follow UniiChat’s release at `0500bf6`. Where it differs from the gist the guide was first written from, they follow the release: its prompt’s closing paragraph, the turn message, the single too-long note, patient summary calls, the clipped source of an unanswerable compaction, 64 builds in message order, view sizes and flattened merge inputs, independent view batches, wrong-line zoom answers, tool-call logging, cut attempts and the notes of a turn without a reply, `spawn` and `tell`, report text and the stop that ends agents. Where this port still differs from the release, the requirement says so, and [the references](10-references.md#where-this-port-differs-from-uniichat) list each difference.

## One endless chat and permanent log

- One ongoing chat and permanent message identities: [architecture](01-architecture.md), [memory and views](02-memory-tree-views.md), [turns and coordinator](04-turns-and-coordinator.md). Test stable root/IDs after reopen and independent fresh model contexts.
- Exact permanent originals with kind, text, UTF-8 size and date: [memory and views](02-memory-tree-views.md), [turns and coordinator](04-turns-and-coordinator.md). Test original round-trip recall, including imports, visible error text and images.
- All six kinds (`user`, `unii`, `tool`, `echo`, `work`, `note`): [memory and views](02-memory-tree-views.md), [turns and coordinator](04-turns-and-coordinator.md), [tools and recall](05-tools-and-recall.md), [background agents](06-background-agents.md). A tool record contains its name and JSON input; a work record contains the actual named final reply.
- Append-only semantic history and one writer: [memory and views](02-memory-tree-views.md), [host and lifecycle](08-host-and-lifecycle.md). Verify the single owner; native commits are atomic.
- No thinking in OptChat memory: [turns and coordinator](04-turns-and-coordinator.md). Native operational reasoning/signatures remain, as explicitly requested by the user; test both memory exclusion and protocol preservation.
- Tool output over 30,000 characters clipped as UniiChat’s [clip](https://github.com/VictorTaelin/UniiChat/blob/0500bf6a8ea4bf0ce047488562022b1b6532cc30/Clip.ts#L18-L43) does, its first 15,000 and last 14,936 around `[... N characters cut ...]`, except a native read page in the model’s context: [tools and recall](05-tools-and-recall.md). Test complete source head/tail, Unicode unit, diagnostic-inclusive echo/model text, the exact marker and the unclipped page.
- Replies trimmed and empty ones not logged; a tool result’s echo is text only, an `[image]` line for each image: [turns and coordinator](04-turns-and-coordinator.md).
- Other long text split losslessly into consecutive records: [turns and coordinator](04-turns-and-coordinator.md), [tools and recall](05-tools-and-recall.md). Test concatenation equality and whole original provider delivery.
- Daily JSONL partitioning and separate view files are replaced by native storage/doc addressing, as requested; permanent behavior is not replaced with disposable exports.

## Binary tree and exact short-source behavior

Sources: UniiChat’s [Memory.ts design](https://github.com/VictorTaelin/UniiChat/blob/0500bf6a8ea4bf0ce047488562022b1b6532cc30/Memory.ts#L1-L26), [node sources](https://github.com/VictorTaelin/UniiChat/blob/0500bf6a8ea4bf0ce047488562022b1b6532cc30/Memory.ts#L575-L586) and [build](https://github.com/VictorTaelin/UniiChat/blob/0500bf6a8ea4bf0ce047488562022b1b6532cc30/Memory.ts#L726-L756).

- Leaves and aligned power-of-two parents, permanent `id+n` addressing: [memory and views](02-memory-tree-views.md), [tools and recall](05-tools-and-recall.md). Test range arithmetic, alignment and exact span validation.
- Short leaf is its exact `kind: text` source; short parent is both lines, each flattened, joined by a newline, as UniiChat’s merge input is: [memory and views](02-memory-tree-views.md). Test no model call and no trimming/rewording.
- Long source produces a one-line target near 512 bytes: [memory and views](02-memory-tree-views.md), [summary tasks](03-summary-tasks.md). Test actual UTF-8 counts; retain the shortest final candidate, a few bytes over allowed, as UniiChat’s build does.
- Build a node once, never regenerate an existing built node: [memory and views](02-memory-tree-views.md), [summary tasks](03-summary-tasks.md). Test atomic publication and crash before/after that commit.

## Saved view, rollback order and sawtooth

Sources: UniiChat’s [view sizes](https://github.com/VictorTaelin/UniiChat/blob/0500bf6a8ea4bf0ce047488562022b1b6532cc30/Memory.ts#L145-L148), [view batches and due merges](https://github.com/VictorTaelin/UniiChat/blob/0500bf6a8ea4bf0ce047488562022b1b6532cc30/Memory.ts#L831-L956) and [view rendering](https://github.com/VictorTaelin/UniiChat/blob/0500bf6a8ea4bf0ce047488562022b1b6532cc30/Memory.ts#L1005-L1018); the due-order oracle is the rollback push of [the gist’s §3.1](https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449/3c190e06f34aba0c69f49042c526093269604935).

- Oldest-first complete coverage with formatted `id+n|text` lines: [memory and views](02-memory-tree-views.md). Test no gaps/overlap in the renderable prefix and full preceding coverage at fresh-turn admission.
- Newlines rendered as spaces; no dates; no raw long messages or partial snippets: [memory and views](02-memory-tree-views.md), [tools and recall](05-tools-and-recall.md). Dates are retrieved through `date`. Short exact-copy leaf nodes remain legitimate nodes.
- Most-due built sibling parent, measured from the pair’s last message, oldest tie: [memory and views](02-memory-tree-views.md). Test the `T=10` counterexample and compare against the supplied rollback-push ordering over 0–20,000 steps at that algorithm’s own budget. Do not implement the sample rollback list as the production byte-budget view.
- Append only at the tail between batches; a view’s size is its lines’ node text in UTF-8 bytes, as UniiChat counts it; threshold strictly over 128,000, target at most 64,000: [memory and views](02-memory-tree-views.md). Test unchanged older prefix and delayed-parent/pending-batch behavior.
- Only built parents may merge; incomplete reductions resume at later message boundaries: [memory and views](02-memory-tree-views.md). A completion supplies missing text but does not independently invent a new merge boundary.
- Save and reload the exact view rather than reconstructing it: [memory and views](02-memory-tree-views.md), [host and lifecycle](08-host-and-lifecycle.md). Test byte-identical no-new-message reopen.
- Do not replace byte budgets with fixed K lines per level: [memory and views](02-memory-tree-views.md), [validation](09-validation.md).

- Same system prompt and offered tools, with tool use disabled; UniiChat sends a compaction no tools, which this port defers with the caching work: [summary tasks](03-summary-tasks.md), [turns and coordinator](04-turns-and-coordinator.md). Test request schemas and reject a tool-using candidate without running tools.
- Independent saved 16,000–32,000-byte compaction sawtooth: [memory and views](02-memory-tree-views.md). Test initial reduction, tail appends, the >32,000 trigger, and that a main batch only appends to it.
- Leaf context ends before its source; merge context through its own last message; stop at first missing leaf: [memory and views](02-memory-tree-views.md), [summary tasks](03-summary-tasks.md). Test no future context and no placeholders.
- Exact leaf/merge task wording, complete source, 512-dash ruler, source IDs/range and parent-detail recovery: [summary tasks](03-summary-tasks.md), [turns and coordinator](04-turns-and-coordinator.md). Compare fixtures against linked source.
- Overlength retry with UniiChat’s single note after the same view and task: measured byte size, safe 512-byte prefix and cut marker, never a try’s words or thoughts: [summary tasks](03-summary-tasks.md). Test preserved source/context and the one note of the last line.
- At most five lines; keep the shortest, allow slight overrun rather than truncating a written line: [summary tasks](03-summary-tasks.md). Test worsening later candidates.
- While Harness retries are enabled, every failure but the model’s own (a provider error, retryable or not, a thrown error or an unavailable model) waits pi-ai’s backoff and asks again, past pi-durable’s retry bound, as UniiChat’s patient calls do; a reply without a line, the model’s own failure, publishes the shortest earlier line or the flattened source cut to 512 bytes: [summary tasks](03-summary-tasks.md). - With Harness retries off, a failed call becomes retry-eligible at the next message, including later assistant/tool/result records: [turns and coordinator](04-turns-and-coordinator.md), [summary tasks](03-summary-tasks.md). Test fresh-input gating, duplicate request replay and no timer loop.
- Up to 64 concurrent calls, UniiChat’s `JOBS`: the nodes ready up to the 64th unbuilt leaf, in message order by where each one’s context ends, a merge first at a tie; a parent waits for both children and a failed node keeps its place: [summary tasks](03-summary-tasks.md). Test every admission transition.
- Readiness queues, never repeated full-tree work scans: [memory and views](02-memory-tree-views.md). Test historical growth without rediscovery scans.
- Cheap summary model/effort supplied by the host, with no default; UniiChat’s default compactor, `haiku-5.5` at high effort, is an example rather than a provider requirement: [summary tasks](03-summary-tasks.md).

## All thirteen mistakes to prevent

Source: [the gist’s §7, Mistakes to avoid](https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449/3c190e06f34aba0c69f49042c526093269604935). The release has no such list; its code avoids each mistake.

1. Pair age from first message → [memory and views](02-memory-tree-views.md) uses last-message age.
2. Merge every message → [memory and views](02-memory-tree-views.md) uses persistent high/low batches.
3. Rebuild view at turn/restart → exact saved refs and pending state in [memory and views](02-memory-tree-views.md), [host and lifecycle](08-host-and-lifecycle.md).
4. Fixed K lines per level → UTF-8 byte budgets in [memory and views](02-memory-tree-views.md).
5. Raw/partial unsummarized messages in view → preceding-leaf gate and built-only rendering in [turns and coordinator](04-turns-and-coordinator.md), [memory and views](02-memory-tree-views.md).
6. Contextless summaries or different system → frozen contextual prefix and shared final prompt/schema contract in [summary tasks](03-summary-tasks.md), [turns and coordinator](04-turns-and-coordinator.md).
7. Trust model byte counting → ruler, measured bytes, cut and the too-long note in [summary tasks](03-summary-tasks.md).
8. Excessively small summary-line budgets → 512-byte target and value-priority prompt in [memory and views](02-memory-tree-views.md), [summary tasks](03-summary-tasks.md), [turns and coordinator](04-turns-and-coordinator.md); short exact sources are still valid.
9. Log thoughts → omit from OptChat semantic records in [turns and coordinator](04-turns-and-coordinator.md), preserve native protocol metadata explicitly.
10. State in system/tools → variable suffix only in [turns and coordinator](04-turns-and-coordinator.md).
11. Carry previous context across turns → native reset plus acceptance-time freshness in [architecture](01-architecture.md), [turns and coordinator](04-turns-and-coordinator.md).
12. Multiple writers/unflushed commits → one process per database file and native atomic commits in [host and lifecycle](08-host-and-lifecycle.md).
13. Scan tree for work → readiness queues in [memory and views](02-memory-tree-views.md).

## Representation and execution contracts

Apply these contracts consistently:

- Native Docs/Entries replace daily files; immutable semantic content remains permanent.
- Native reset means fresh request context while retaining provider affinity identity; hidden provider-side continuity must not be assumed.
- Inputs arriving during pre-call preparation remain distinct inputs in the reserved logical turn; UniiChat joins the messages waiting as its call starts into one turn message. Inputs arriving after native completion with no genuine pending work must instead be fresh, and so must inputs a failed run left queued or a turn ended before dispatching.
- Stock steering modes place inputs at tool-round boundaries: the round’s calls finish and the next model request reconsiders, as UniiChat delivers a message; nested-call/replay behavior retains its native semantics. See [turns and coordinator](04-turns-and-coordinator.md).
- A message steered into a turn whose run ends in the moment between its preparation and its submission continues that turn's context, as a steer placed at the run's end does: pi-durable 1.4.0 offers no submission that waits only while busy. One found prepared and unsubmitted after its turn ended starts a fresh turn.
- Thoughts are omitted from semantic memory, not forcibly stripped from native protocol records, to preserve provider protocol continuity.
- Unicode scalar units, delimiter accounting and non-tool record/page sizing are this port’s conventions; UniiChat counts JavaScript string length (`CAP`) and ends a page after its last newline.
- Tool output-source conformance remains required behavior, not an optional omission; provider caching is pi-ai’s own.
- Every changed document or task shape migrates through pi-durable; existing conversations are never cleared. See [host and lifecycle](08-host-and-lifecycle.md).
- Preserve native interruption/replay semantics. External-byte recovery, exactly-once external actions, fixed cache economics and guaranteed model success are not guarantees of this plan.
